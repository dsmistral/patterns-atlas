3 · Name the move

Pattern P07 — Build an auxiliary object. When a direct route is blocked because the fact you need runs through an object the problem never gave you — a point, a line, a circle, a function, a polynomial, a second copy — construct that object yourself. Build it by a defining property you can compute with (a recipe, coordinates, an equation), verify the property before you use it, prove the target claim with the object in place, and then clear the object away: the final statement mentions only the original objects.

Or, in words: the problem forgot the scaffolding — so put it up yourself. But scaffolding has rules: it must be bolted to something real (a defining property, checked), strong enough to stand on (the property you needed), and it must come down at the end, leaving the theorem on its own feet. An object you cannot define is a wish; an object you cannot remove is a different theorem.

Box P07.A — the builder's three demands, and what breaks when each fails.

  1. Name the job before the object. Not "draw a helpful point" — the job first: "I need a point that makes these two broken paths comparable", "I need one quantity that both legs of the claim speak through". The job tells you what to build; the object is a solution to the job, and different builders may answer the same job with different objects (Example 2 builds a point and a circle for the same theorem). What breaks: an object built without a job cannot be wrong — it can only be useless, and useless objects are seductive because they decorate the page.
  2. Build by a defining property you can compute with. "The reflection of \(B\) in the river" is a recipe — \((6,2) \mapsto (6,-2)\) — and the recipe hands you a property for free: the river is the perpendicular bisector of \(BB'\). Every build on this page is a recipe: reflect, draw the parallel, complete the rectangle, write the equation, reverse the row. What breaks: a build with no recipe has no properties, and a proof step that cites it is citing a wish (block 5 calls this the decoration, and shows the grid catching one).
  3. Verify the property before use — your construction is a claim too. The reflected point is not "probably" equidistant from the bank: it is exactly equidistant, by the recipe, and one line of arithmetic certifies it. P01's pinning discipline applies to objects you built yourself, doubled: you invented the object, so you owe it a definition and a check. What breaks: a build whose claimed property fails is a phantom — it looks constructive and proves nothing (block 5's radius-7 circle is the exhibit).
  4. Cash out and clear away. The theorem statement, at the end, mentions only original objects. The river answer is "touch at \((4,0)\), walk \(6\sqrt{2}\)" — no \(B'\). If the scaffold will not come down — if your final claim still needs the auxiliary object to make sense — then you have proved a different claim, about a different configuration, and you should say so.

Three-key diagnosis. The claim type: anything, but the signature is a prove or compute claim whose direct route is blocked while a related, constructed route is nearly visible. The problem shape: the givens are complete but inert — the connecting relation (bisection, straightness, symmetry, a recurrence) runs through an unnamed object. The tools at hand: the construction kit (reflect, draw the parallel, complete the rectangle, write the equation, take a second copy) plus P02's small cases to test a candidate build before trusting it, and P03's malice to attack your own construction once it is up.

When does P07 apply? Not every problem needs a build — most die to pinning, tables, or hostile cases, and building when you did not need to is its own failure (block 5). The honest trigger: you have pinned the claim (P01), checked the small cases (P02), attacked the extremes (P03), and the route still runs into a wall of the form "this would be easy if I only had — a point there, a line through that, an equation for this". The sentence names your build. Finish the sentence, and you have the object.
