The census taker has one repair left, and it fails in a way worth watching. Suppose he pencils the shadow in as row \(9\). The patched list has a new ninth row, beginning \(1,1,1,1,1,1,1,1\) — and at position \(9\) it shows some digit, whatever digit the shadow itself carries there. The rule consults it: write \(1\) if it is not \(1\), write \(2\) if it is \(1\). Either way the new shadow differs from the patched row in position \(9\) — and nothing has changed in positions \(1\) through \(8\), so the new shadow still differs from every old row in its old position. The repair is not merely useless; it is self-refuting: each patch hands the machine its next digit. Add the shadow, and the shadow's own successor appears; the machine walks one row behind him forever, on whatever he writes, at a cost of one glance per row.

Notice what the argument did not do. It did not check his eight rows for errors — they can all be correct. It did not hunt for the shadow by searching his list — no search was run. It built the shadow from the list's own geometry: the diagonal is not a lucky feature of this particular list, it is a consequence of listing — the moment rows have row numbers and entries have positions, the diagonal exists. That is why the refutation hits every list at once, and why it deserves a name of its own.

3 · Name the move

P14 · The diagonal argument — build the one object the enumeration missed

Shape of the claim. "Rows \(1, 2, 3, \ldots\) exhaust the collection." The claim is an exhaustiveness claim about a numbered list, and the list can be infinite — that is not a weakness but the move's natural habitat.

The move. Do not search the list. Build one object \(s\) whose \(n\)-th coordinate is chosen to differ from the \(n\)-th coordinate of row \(n\) — one controlled disagreement per row, charged to every row at once. Then \(s\) cannot be row \(n\) for any \(n\), because \(s\) and row \(n\) disagree in coordinate \(n\). The claim of exhaustiveness dies by the meaning of list.

When to reach for it. When someone claims a complete list, catalogue, survey, or table — of numbers, of subsets, of programs, of answers — and the rows can be numbered. When the claim is "everything appears," the response is not "you missed something," it is "here is something you provably missed, built to order."

The move, in words a page long: an enumeration is a function — row number in, member out — and functions can be questioned point by point. Question it on the diagonal: at input \(n\), compare row \(n\)'s \(n\)-th coordinate with your object's \(n\)-th coordinate. Build your object so the comparison always comes out "different." The diagonal is the only place where every row and every coordinate meet exactly once, which is why the construction gets one free shot at each row — and needs only one.

The three demands

The construction must clear three gates, and §5 is a gallery of failures at each:

  • Existence. The rule must define an object at all. "Write \(1\) unless the row's digit is \(1\), then write \(2\)" builds a digit at every position — the object exists. A rule like "differ from row \(n\) in every coordinate" builds nothing usable; the demand is one coordinate per row, not all of them.
  • Membership. The object must belong to the claimed domain. The shadow of a list of reals is a real; the shadow of a map from \(S\) to its subsets is a subset of \(S\). When the flip leaves the domain, the "refutation" refutes nothing — the missed object was never required to be on the list.
  • Difference. The disagreement at coordinate \(n\) must be a genuine disagreement of objects, not of spellings. Two decimal strings can name one number; the rule must be safe against that (the \(1\)-or-\(2\) rule is one way; §5's first exhibit is the accident it prevents).

Where the move appears, and its three-key signature

Appearances. Lists of decimals (§4's second example: the reals refuse enumeration). Maps to subsets (§4's first example: Cantor's theorem — no function onto a power set). Predictors of program behavior (§4's third example: the halting flip). Surveys of questions about themselves (§5: Russell's set). Any table whose rows are answers and whose columns are cases.

Three keys. The move applies exactly when all three turn:

  1. A numbered claim. The exhaustiveness claim comes with an index: row \(n\) is a definite object, and "all rows" is a well-defined totality.
  2. A controllable coordinate. Each row exposes at least one feature you can inspect and your object can disagree on — a digit, a membership, a behavior, an answer.
  3. A closed domain. One object built by disagreeing per row stays inside the claimed collection, so "it is not on the list" contradicts the claim rather than the setup.

When the third key jams — when the flip escapes the domain — you have not refuted the list; you have discovered that the domain has an outside (§5, second exhibit). When the first key jams, there is no list to refute, only an unpinned claim — which is a job for P01, not P14.
