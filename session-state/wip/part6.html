Example 3 · No predictor predicts every program — including itself

Moves used: P01 pinning what "predictor" must mean · P07 building the flipper program nobody supplied · P11 assuming the predictor is complete · P14 flipping the prediction along the diagonal.

The digit table was theater, the subset flip was the skeleton — and here is the move wearing its most startling costume. The claim: some program \(P\) is a halting predictor: feed it a program \(X\) and an input \(x\), and it answers, correctly for every pair, whether \(X\) run on \(x\) halts or loops forever. Read as a table: rows are programs, the interesting column is "what does row \(X\) do on input \(X\)," and the claim is that \(P\)'s answers fill that column completely and correctly.

Build the flipper, P07-style. It is a program \(F\) that, on input \(y\): asks \(P\) for its prediction about the pair \((F, y)\) — and does the opposite. If \(P\) predicts "halts," \(F\) loops; if \(P\) predicts "loops," \(F\) halts. \(F\) is a perfectly definite program: it consults \(P\) and behaves contrarily. Now ask the diagonal question: what does \(F\) do on input \(F\)? By construction, the opposite of what \(P\) predicts for \((F, F)\). So \(P\)'s prediction about \(F\)'s own run is wrong — always, whatever it says. The predictor cannot be complete: the one program built out of it refutes it.

An honesty label, before the sketch gets treated as a proof. Sketch — two missing pieces. First, "program" needs a formal meaning before "every program" can be claimed about anything; second, the flipper quietly assumes that \(F\)'s description of itself — feed \(P\) the pair \((F, y)\) — is a legal program input, i.e. that programs can be quoted to programs. Both gaps are closed by the universal machine formalism, and that construction is a spine destination deferred by name to a later page (the arithmetization of syntax). The sketch becomes a theorem exactly when "consult \(P\), do the opposite" is certified a program; with that certificate, the proof is the two sentences above. The historical version is Turing's, from 1936, in a section pointedly titled "Application of the diagonal process": the column of predicted behaviors is a list, the flipper is the shadow, and the list of programs cannot be exhaustive about its own members.

What the sketch hides can be checked honestly on a toy small enough to census. Three programs, whose inputs are program numbers \(1, 2, 3\): \(t_1\) halts on every input; \(t_2\) loops on every input; and \(t_3\), the skeptic, on input \(i\), does the opposite of what the current published predictor's table says for program \(i\). A claimed predictor for this universe publishes a table \(p = (p(1), p(2), p(3))\) of halts/loops predictions for each program's self-run. Row by row: against \(t_1\), the table must say "halts" to survive row \(1\); against \(t_2\), "loops"; and against \(t_3\) — no entry survives, because \(t_3(3)\) is defined as the opposite of \(p(3)\), whatever \(p(3)\) is. Of the eight possible tables, none survives row \(3\): six die earlier as well (wrong about \(t_1\) or \(t_2\)), and the remaining two die at the skeptic. The refutation is one line, and it is the same line as the digit machine's: the row built from the table cannot appear in the table.

The toy's honest small print: \(t_3\) was put in the universe by hand, graciously. The real theorem's content is that for actual programs the skeptic does not need a sponsor — the universe of programs is closed under "consult and contradict," which is precisely the deferred formalism. This is also why the move here is genuinely new rather than Example 1 in costume: for finite tables, "all behavior-functions on a set" always outruns the set itself (that is Cantor's theorem); the halting result says something subtler — that even the countable, text-bound world of programs contains its own skeptics.
