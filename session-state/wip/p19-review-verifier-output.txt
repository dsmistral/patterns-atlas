## Run 1 — 180 PASS / 16 FAIL — ALL SIXTEEN VERIFIER-SIDE, page fully clean
The verifier did its adversarial job on itself: every VFAIL was a defect in the
verifier's own checks, and none indicted the page.
  - VB table tolerances too tight for the page's honest roundings: the page prints
    E-values as 2-significant-figure approximations (0.00195 of 0.001953125,
    0.00171 of 0.001708984375, 0.000315 of 0.000314712); fixed with an explicit
    per-row tolerance array (ETP) matched to the printed precision.
  - VB floor-check slack too tight: the good-fraction column prints floors at
    their printed decimals (0.998 is the 3-decimal floor of 0.998046875; 0.9996
    of 0.999685; 0.9999 of 0.999904); fixed with a per-row slack array (FDP),
    keeping the strict no-overclaim half (1 - E >= printed).
  - VB pentagon key lookup did not normalize unordered pairs ("52"/"41" were
    looked up instead of "25"/"14"); fixed with min/max key normalization.
  - VC String.replace only replaces the FIRST occurrence: three doctored clones
    (E-value, C(32,10), Paley bound) still contained the genuine needle later in
    the page, so the must-fail assertion failed. Fixed with split().join() global
    replacement (the E-value appears 4 times, the Paley bound twice).
  - VD chunk simulation dropped the newline BETWEEN chunks — the verifier's own
    loader test committed the exact join() boundary bug it was testing for. Fixed:
    each 60-line chunk now ends with its newline, exactly like read_file chunks.
  - VD line count: split("\n") on a file ending in "\n" yields 205 parts for 204
    lines; the check now asserts 205 split parts AND 204 counted newlines.
  - VE needle case: "Its mean is its probability" (the page capitalizes).
No page byte was changed in this round — the page was already correct.
