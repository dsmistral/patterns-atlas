RUN HISTORY (honest):
- The verifier's first queens engine draft had a broken explicit-stack resume
  step (wrong counts, e.g. n=4 -> 1); rewritten as a clean descend/backtrack
  loop before any verdict was accepted. No verdict was taken from the buggy run.
- The first orbit engine used 8 matrices applied to 1-based coordinates with a
  sign-flip normalization; the normalization was wrong (13 canonical keys,
  garbage histogram). Replaced by explicit dihedral coordinate maps on 0-based
  cells; canonical-key counting then gave 12 orbits, sizes {8:11, 4:1}.
- The trapezoid Li route at N=2^17 lacked the precision for 4 d.p. at 10^8
  (error +0.0085, as the O(h^2) bound predicts for a convex integrand). Fixed
  honestly: N=2^21 with a quadratic-convergence receipt (error shrinks x4.00
  per doubling) and a Richardson extrapolant matching the page value to
  within 5e-5. The page's 4 d.p. value 5762209.3754 is additionally confirmed
  by the lab's convergent series (the exact route), so the trapezoid's
  residual +3e-5 error bar is recorded, not hidden.
- One injection initially MISSED for the same reason (the poisoned 4th
  decimal was inside the trapezoid's own error bar); injections were
  redesigned to poison the 3rd decimal, far outside any engine's error bar.
- The published file's V15 loop uses direct cube arithmetic where the run
  used a precomputed cube table; identical semantics, re-verified after the
  rewrite (un=2, ord=4).
